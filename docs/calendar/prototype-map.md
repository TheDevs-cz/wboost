# Kalendáře — technical map of the prototype

Source: `docs/calendar/prototype/wboost-prototyp.html` (artifact `ab3b9009-cd72-4e15-aa3e-e6506f4b9d25`, version `1794398222-edc2`, 9000 lines, 1 477 578 bytes).
All `L123` references are line numbers in that file. Lines are long (up to ~2 300 chars in the calendar code), so read them with a wide cut.
Companion: `docs/calendar/handoff.md` (product intent; wins over the prototype where they differ).

The prototype is one IIFE (`<script>` L3264–L9000) that renders everything by string concatenation into `#view` and re-renders the whole workspace on every change (`calRe`, L5866). Nothing in it is worth porting structurally; what must be ported are **the data shapes, the geometry, the layout formulas, the interaction rules and the Czech copy**. This document records those.

Conventions used below:

- **unit** = one canvas unit of the prototype's 1000 × 468 page.
- `B` = bleed in units (`calBU`, L5321).
- "dead" = code present in the file with no markup that can trigger it.

## 2. State and data model

Persistence: `localStorage['wb-cal-' + projectId]` = JSON array of calendar objects (L5309–L5310). `hist`, `fut`, `_dirty` are stripped on save; **`ui` is saved** (so the open step, selection, zoom, `link` survive reload). Images are stored inline as data URLs.

### 2.1 Calendar object `c`

Created by `calNew` (L5382), verbatim:

```js
{ id, name: `Stolní kalendář ${y}`, year: y, type: 'week', photo: null, L: null, gen: calG(null), step: 1, done: false, created: Date.now(), ui: { sel: null, part: null, pg: 1 }, hist: [], fut: [] }
```

with `y = new Date().getFullYear() + 1` and `id = 'k' + Date.now().toString(36)`.

### 3.3 Bleed, binding band, layer order

- **Bleed** is not a separate structure: boxes simply extend past the trim (`x < 0`, `x + w > CW`, …). The SVG `viewBox` is `-B -B CW+2B CH+2B` (L5298). In the editor (`!o.final`) the bleed ring is overlaid with a 45° hatch (`#E0708A`, opacity .35, 6-unit pattern) and the trim edge gets a dashed rect (`#D9486A`, 1.2, dash `6 4`) (L5297). Pages rendered without `bleed` (thumbnails, step 4 pages, client view) use `viewBox 0 0 1000 468`, so bleed content is just cut off.
- **Binding band**: there is **no band element**. `calSpiral()` returns `''` (L5111). The only fixed thing is `calHoles()` (L5112): 38 rounded squares `14 × 14`, `rx 2`, at `x = 16 + i·26`, `y = 13`, fill `#F6F5F8`, `pointer-events: none`, painted **on top of everything on every page kind** (L5296). `CTOP = 40` (40/468 = 8.55 % of the height) is used as: a snap line (L5824), the top of full-page placeholders on cover/special pages, the default top of the month text. The grey strip seen in the prototype is the default **Hlavička** background `#CBC7D1` (`CK.band`).
- **Paint order of a week page** (L5118–L5120, L5295–L5297): paper rect (`#F6F5F8`, incl. bleed, `data-el="bg"`) → Pozadí layers → elements in **reverse `L.z`** (so default: photo, cal, head, month, wk, cap, logo, qr) → holes → hatch + trim line. Each element is an SVG group/element carrying `data-el="<key>"`; kalendárium children carry `data-cp="<part>"`.

## 4. Rendering

### 4.1 Technology

Everything is **one inline SVG string per page** built by `calPageSvg(pg, o)` (L5114–L5299); no canvas, no DOM text layout. `o = { L, year, proj, pid, gen, ov, bleed?, editor?, final? }`. Root: `<svg viewBox=… font-family="Outfit, Arial, sans-serif" role="img" aria-label="<page title>">`.

The editor's selection frame, handles, tag, part highlight boxes and guides are **HTML `<span>`s in an absolutely positioned overlay** (`.cal-ovl`, `calOver` L5806–L5821) placed over the SVG; step 5's pencil / plus / warning / comment buttons likewise (`.cal-5o`, `calOver5` L5568–L5575). Positions come from the box model (`b.x * s`) for elements and from `getBoundingClientRect()` of SVG nodes for parts and step-5 buttons.

Text is never measured for layout, except the auto-grow of `month`/`wk` (`getBBox`, §6.9). All wrapping and offsets use **character-count estimates** (`0.52`–`0.6 × font size` per character).

### 4.2 Units

| Constant | Value | Meaning | Tied to the wrong 210 mm page? |
| --- | --- | --- | --- |
| `CW`, `CH` | 1000, 468 | Page in units | ratio only |
| `CAL_MM` | 0.21 | mm per unit (`210 / 1000`) | **yes** — at 310 mm it must be 0.31 |
| `CAL_PT` | 1.68 | units per pt (`0.3528 mm / 0.21`) | **yes** — at 310 mm it is `0.3528 / 0.31 = 1.138` |
| `calU(pt)` | `+(pt * CAL_PT).toFixed(2)` | pt → units (all type sizes, line thickness) | yes |
| `calBU(c)` | `mm / CAL_MM` | bleed → units | yes |
| mm panel values | `mm = (v) => +(v * CAL_MM).toFixed(1)` (L5716), back `v / CAL_MM` (L6043) | X/Y/Š/V | yes |
| mm style values → units | `/ CAL_MM`: photo radius, border, shadow blur/offset (L5176–L5181), `month.pad`/`cap.pad` (L5188, L5283), `cal.iconS` (L5200), `moon.sizeMM` (L5200), per-cell icon size (L5261) | | yes |
| dpi | `photoW / (E.photo.w * CAL_MM / 25.4) / pz` (L5529) | | yes |
| crop marks | `gap = 2 / CAL_MM`, `len = 6 / CAL_MM` (L5541) | | yes |

Because every user-facing size is stored in pt/mm and converted through these two constants, the stored *values* are fine; what is wrong is their on-screen proportion (a 19 pt number is drawn 1.68/1.138 = 1.48× too large relative to a 310 mm page). The default pt sizes were chosen by eye under the wrong scale — after fixing the conversion they will look ~32 % smaller relative to the page. Decide whether to scale default pt sizes by 310/210 to preserve the prototype's look (handoff: "proportions seen in the prototype remain valid").

Constants that are **raw units** (not mm-derived; convert as fractions of the page when porting): row padding `16`, gap number↔text `10`, shift column width `16` (+1 gap, +6), compact threshold `38`, shift-column threshold `34`, compact scale base `30`, icon slot extra `4`, empty slot `20`/`24`, `area = b.h − 6`, min box `20 × 12`, nudge `1`/`10`, link tolerance `0.6`, part-offset snap `0.75`, rounding grid `0.5`, holes, `CTOP 40`, min event box `20 × 4`, min icon cell `6`, min holiday wrap width `20`.

### 4.4 Kalendárium row layout (L5190–L5282)

Setup:

```js
b = cal box clipped to the trim: x0 = max(b0.x, 0), y0 = max(b0.y, 0), x1 = min(b0.x + b0.w, CW), y1 = min(b0.y + b0.h, CH); w = max(20, x1 − x0), h = max(20, y1 − y0)
n = pg.days.length; side = C.side; area = b.h − 6; rh = area / n; compact = rh < 38; sc = compact ? Math.min(1, rh / 30) : 1; pad = 16
```

The background rect uses the **unclipped** box (fills the bleed) with `C.bg` / `C.bgOp`. Default 7-day layout: `rh = 356 / 7 = 50.86` → normal mode. 14 rows in the same box: `rh = 25.43` → compact, `sc = 0.848`.

Number column:

```js
numK = (d) => (d.hol ? 'numHol' : d.wd === 6 ? 'numSun' : d.wd === 5 ? 'numSat' : 'num')
nMax = max of the four number sizes (units); nCap = rh * (compact ? .78 : .74); nSzOf(k) = min(calU(St[k].size), nCap); nSz = min(nMax, nCap)
numX = side === 'end' ? b.x + b.w − pad : side === 'middle' ? b.x + b.w / 2 : b.x + pad
above = C.dayPos === 'above' && !compact; dS0 = calU(St.day.size) * sc
numW = above ? Math.max(nSz * 1.3, (C.dayFmt === 'short' ? 2 : 7.5) * dS0 * .6) : nSz * 1.3
na = St.num.align || side; column [cL, cR] = end: [numX − numW, numX], middle: [numX − numW/2, numX + numW/2], start: [numX, numX + numW]; nx = start → cL, middle → centre, end → cR
```

Number baseline: `t + rh/2 + nz*.36` (`nz = nSzOf(nk)`); with `above`: `H = dS*1.2 + nz*.74; top = t + (rh − H)/2;` weekday at `top + dS*.85` (aligned by `C.dayAl || na`), number at `top + H`.

Text column:

```js
tx = side === 'end' ? numX − numW − 10 : side === 'middle' ? numX + numW / 2 + 10 : numX + numW + 10
an = side === 'middle' ? 'start' : side            // text-anchor of the text column
```

Outer zone (the side away from the numbers; for `middle` it is the left):

```js
icL = side !== 'start'; edge = icL ? b.x : b.x + b.w; ax = (off, w = 0) => (icL ? edge + off : edge − off − w)
shCols = G.shift.on ? G.shift.c : []; cw = 16; shW = shCols.length && !compact && rh >= 34 ? shCols.length * (cw + 1) + 6 : 0
iw = (C.iconS || 4) / CAL_MM; isw = iw + 4; order = calIconKeys(G)
moonD = Math.min((St.moon.sizeMM || 3.4) / CAL_MM, rh * .8)
slotW = (k) => (C.icCell ? C.icCell : k === 'moon' ? Math.max(isw, moonD + 4) : isw)
lblOn = C.iconLbl && G.waste.on; lS = calU(St.iconTxt.size) * sc; lblW = lblOn ? (longest place length) * lS * .56 + 8 : 0
zone0 = shW ? shW : pad; slotX[k] = running x from zone0
gm = !compact && C.icGrid !== 'row' ? (C.icGrid || '4') : null; gW = Math.max(C.icCell || 0, isw); if (gm) zx = zone0 + (gm === '4' ? 4 : 2) * gW
emptySlot = !order.length && C.icon; zoneEnd = zx + (emptySlot ? 24 : 0) + lblW + (order.length || emptySlot ? 6 : 0)
colL = an === 'end' ? ax(zoneEnd) : tx; colR = an === 'end' ? tx : icL ? b.x + b.w − pad : ax(zoneEnd)
```

So from the outer edge inwards: shift columns → icon grid (or icon slots) → place labels → text column → number. In grid mode the zone always reserves 4 (grid `4`) or 2 (other grids) cell widths, even with no icons.

Per row `i`: `t = b.y + i * rh`; a transparent `<rect data-day="YYYY-MM-DD">` covers the row (used by step 5 to place the plus buttons).

**Normal mode** (L5218–L5237). Stacked lines: weekday (unless `above`) → name day (`calNm`) → holiday wrapped to `maxCh = max(8, floor((St.hol.ww || |colR − colL|) / (hS * .52)))` characters → time/season text (unless `time.pos === 'sep'`). Vertical start `y = t + (rh − base)/2` with `base = ((above ? 0 : dS) + nmS) * 1.22` — i.e. **the block is centred on weekday + name only; holiday and time lines extend below**. Each line: `y += size; draw at (tx, y); y += size * .22`. Weekday colour: `C.sun` for holiday or Sunday, `C.sat` for Saturday, else `day.color`. Consecutive holiday lines are wrapped in one `<g data-cp="hol">`.

**Event box** (L5231–L5234), up to 4 events (`calEvs(d, G).slice(0, 4)`):

```js
cL0 = min(colL, colR); cW0 = |colR − colL|; EB = St.ev.box || {}
bx = cL0 + (EB.x ?? 0); bw = max(20, EB.w || cW0)
by = t + (EB.y ?? min(rh − eS * 1.5, (rh + ((above ? 0 : dS) + nmS) * 1.22) / 2 + nmS * .35)); bh = max(eS * 1.3, EB.h || (t + rh − 2 − by))
ea = St.ev.align || an; va = St.ev.valign || 'top'
lines = events.flatMap(wrap to max(6, floor(bw / (eS * .52))) chars); lh = eS * 1.2; h = lines.length * lh
```

Text never moves other parts. In the editor (`o.editor`) the box is drawn as a rect `fill #e5484d @ .04, stroke #e5484d @ .55, width .7, dash 2.5 1.5` with `data-cp="ev" data-evbox="1"` — **in every row, whenever the editor is shown, whether or not Akce is selected or even enabled** (§10 item 6). Overflow flag: `if (h > bh + .5) G._evOv[iso] = lines.length; else delete`.

**Time/season as its own block** (`time.pos === 'sep'`, L5236–L5237): anchor at the left / centre / right of the text column, `fz = min(tS, rh * .4)`, y = top `t + 3 + fz`, bottom `t + rh − 3 − fz*.2`, middle `t + rh/2 + fz*.36`.

**Compact mode** (`rh < 38`, L5212–L5216): one baseline `t + rh/2 + dS*.36`: weekday at `tx`; name day offset by `dw = dayName.length * dS * .56 + 8`; then **one** extra text offset by a further `name.length * nmS * .55 + 10`: holiday (cut to 28 chars + `…` when longer than 30), else events joined with ` · ` (when events are on), else the time text. No event box, no overflow check, `dayPos: 'above'` ignored, all sizes × `sc`.

**Lines** (L5244): `if (C.lines && i < n)` — always true, so a line is drawn under **every** row including the last; from `b.x + pad` to `b.x + b.w − pad` at `y = t + rh`; width `calU(C.lineW ?? .7)`; dash `lw*4 lw*3`; dot `0.01 lw*2.6` + round caps.

**Shifts** (L5246–L5250). With columns (`shW > 0`): column `ci` at `x0 = ax(ci * (cw + 1), cw)`; background rect per `bgMode` (`'all'`, or `'alt'` on odd columns) filled `shift.bg` (opaque) or `shift.color` at .14; letters stacked, `lh = min(sS * 1.15, (rh − 6) / count)`, `fs = min(sS, lh * .95)`, empty slot prints `–`. Without columns (compact or `rh < 34`): one text at the outer edge, columns joined with `'  |  '`. Letters: `calShiftCol(d, cc, ci * 3)` (L5031–L5032):

```js
n = Math.round(Date.UTC(d.y, d.m, d.d) / 864e5) + off; k = cc.sh.length; L = Math.max(8, (k + 1) * 2)
cc.cr.forEach((cr, i) => { const q = Math.floor(((n + i * 2) % L + L) % L / 2); if (q < k && !out[q]) out[q] = cr; })   // → one crew letter per shift
```

i.e. each crew works every shift for 2 days, then is off; crews are offset by 2 days; column `ci` is offset by `3·ci` days. Note: the cell prints the **crew** letter for each shift row (R/O/N order), not the shift letter.

**Icons** (L5252–L5280). `has(k)` decides whether day `d` has icon `k` (moon: phase from `moonList` and `calMoonOn`; ev: any event text; time: `calDstOn`; season: `calSeasonK`; waste kind: `calWasteOn`).

- Grid mode (`gm`, the default outside compact): `vis = order.filter(has)`; icons fill cells in order; cell boxes (`H = rh − 4`, `y0 = t + 2`):
  - `'4'`: 4 cells in a row, each `gW × H`.
  - `'2x2'`: 2 × 2, each `gW × H/2`.
  - `'2+1'`: two cells `gW × H*.45` on top, one `2gW × H*.55` below.
  - `'1+2'`: one `2gW × H*.55` on top, two `gW × H*.45` below.
  - Icons beyond the cell count are **not drawn**.
  - Icon size in a cell: `sq = max(2, min(B.w − 1, (B.h − 1) / 1.15, cs.s ? cs.s / CAL_MM : big ? 99 : iw))` (`big` = the double-width cell); alignment `cs.al` start / middle / end; waste and event icons are `sq × sq*1.15`.
  - Editor: dashed violet cells (`#8d7fd6`) with `data-icgrid="4|2" data-cp="icon"`, always drawn.
- Row mode (compact, or legacy `icGrid: 'row'`): each active category/kind has a slot; the day's icons are **packed from the outer edge** in order (`packX`); moon uses `moon.valign`; waste/event icons `iw × min(iw*1.15, rh*.72)`.
- Moon: own image per phase (`St.moon.imgs[ph]`) or `calMoon`. Time: `calClockIco`. Season: `calSeasonIco` by season or the single image. Event: `calIco` with star, per-event image when `ev.iconPer`. Waste: uploaded `T.img` or `calBin2` in `T.color`.
- Empty slot (`emptySlot`): dashed rect `20 × min(20, rh*.62)`.
- Place labels: when `cal.iconLbl` and waste on, the places of the day's collections joined with ` · ` after the icon zone.

**Part offsets** (L5173): every node with `data-cp` gets `transform="translate(x y)"` from `St.off[cp]`; `waste` and `moon` fall back to `St.off.icon`. Number offsets are per style key (`num`, `numSat`, `numSun`, `numHol` separately).

`data-cp` values on nodes: `day`, `name`, `hol`, `ev` (box + text), `time`, `num`/`numSat`/`numSun`/`numHol`, `line`, `shift`, `icon` (grid, event/time/season icons, empty slot, place labels), `moon`, `waste`.

## 5. Generation rules

### 5.1 Pages (`calPages`, L4902–L4918)

```js
pages = [{ k: 'cover', t: 'Titulní strana' }]; n = type === 'two' ? 14 : 7
SP = G.pages.on ? calSpList(G).filter((x) => x.on) : []          // in list order
SP with pos !== 'back' → { k, lay, next, sp: true, t: x.name || calSpName(x.k), range: x.own ? 'Vlastní strana' : 'Speciální strana' }
mon = Monday of the week containing 1 Jan; end = 31 Dec
while (mon <= end) { days = n consecutive days; push week page; mon += n }
SP with pos === 'back'
pages.push({ k: 'back', t: 'Zadní strana', range: SP.some((x) => x.k === 'year') ? 'Kontakty klienta' : 'Přehled roku' })
```

Week page: `{ k: 'week', wk: w1, wl, days, head, t, range }` with `w1 = calIso(mon)`, `w2 = calIso(mon + 7)`.

2027: first Monday = 28 Dec 2026 → 53 seven-day pages (last starts 27 Dec 2027) or 27 fourteen-day pages (last starts 27 Dec 2027 and runs to 9 Jan 2028). Matches handoff G1–G6.

### 5.2 Texts

- **Month** (`head`, L4909): same month → `"<month> <year>"`; else `` `${CAL_M[a.m]} ${a.y === b.y ? '' : a.y + ' '}/ ${CAL_M[b.m]} ${b.y}`.replace('  ', ' ') `` — so `PROSINEC 2026 / LEDEN 2027` across years but `LEDEN / ÚNOR 2027` within a year. Stored upper-cased.
- **Week number** (`wl`, L4910–L4911):

  | `wk.fmt` | 7 days | 14 days |
  | --- | --- | --- |
  | `a` | `${w1}. týden` | `${w1}. a ${w2}. týden` |
  | `b` | `Týden ${w1}` | `Týdny ${w1}–${w2}` |
  | `c` | `T${w1}` | `T${w1}–${w2}` |

- **Page title** `t` = the `a` form with the first character upper-cased (a digit, so unchanged). **Range** = `${a.d}. ${a.m + 1}. – ${b.d}. ${b.m + 1}.`
- **ISO week** (`calIso`, L4899): Thursday of the week, `1 + round((thu − Monday of the week of 4 Jan of thu's year) / 7 days)`.

### 5.3 Name days, holidays, Easter

- `CAL_NAMES` L4880–L4892: array of 12 arrays (January first), index = day − 1, strings; double names already contain `' / '` (e.g. `'Rút / Matylda'`); `''` = no name day (1 Jan, 1 May, 8 May, 5 Jul, 6 Jul, 28 Oct, 17 Nov, 25 Dec). - `CAL_FIX` (L4893), keys `month-day`:

### 5.4 Moon phases (L4984–L4986, L4975)

```js
const CAL_SYN = 29.530588853, CAL_NM0 = Date.UTC(2000, 0, 6, 18, 14) / 864e5;
const calAge = (t) => (((t - CAL_NM0) % CAL_SYN) + CAL_SYN) % CAL_SYN;
const calPhase = (d) => { const t0 = Date.UTC(d.y, d.m, d.d) / 864e5 - 1 / 24, a0 = calAge(t0), a1 = calAge(t0 + 1); if (a1 < a0) return 0; for (let q = 1; q < 4; q++) { const v = q * CAL_SYN / 4; if (a0 <= v && a1 > v) return q; } return -1; };
```

Mean synodic month from the new moon of 6 Jan 2000 18:14 UTC; the day window is shifted by −1 h (CET). This is an approximation (real phases can differ by a day) — which is why the list is user-editable. `calMoonSeed(y)` scans 20 Dec (y − 1) … 12 Jan (y + 1) and stores `{ date, ph }` for days with a phase. Rendering uses `moonList` only (fallback to `calPhase` when the list is missing).

### 5.5 Time and season changes

- DST (text `calTime` L5023–L5026, icon `calDstOn` L4968): last Sunday of March → `'Začátek letního času'`; last Sunday of October → `'Začátek zimního času'`. `ls(m) = lastDay − ((calWd(lastDate) + 1) % 7)`.
- Seasons: **fixed dates** `{ '2-20': 'Začátek jara', '5-21': 'Začátek léta', '8-22': 'Začátek podzimu', '11-21': 'Začátek zimy' }` (month 0-based → 20 Mar, 21 Jun, 22 Sep, 21 Dec), not astronomical. Index 0–3 = spring…winter (`calSeasonK`).
- Several on one day are joined with `' · '`.

### 5.6 Waste rule (`calWasteOn`, L5012–L5013), verbatim


- Weekdays: `T.wds` array, else `[T.wd]`.

## 6. Editor interaction

Everything below is in the editor `pointerdown` handler (L6153–L6202), `calSnap` (L5822–L5837), `calLink` (L5841–L5848), `calOver` (L5806–L5821) and the keyboard handler (L6204–L6211). `s = c.ui.s` = screen px per unit.

### 6.1 Scale and zoom

`calOver`: `aw = stage.clientWidth − 64; ah = stage.clientHeight − 120; fit = Math.max(.3, Math.min(aw / (CW + 2B), ah / (CH + 2B), 1.6)); s = fit * (ui.zoom || 1)`. The canvas div is sized `(CW + 2B) * s × (CH + 2B) * s`; the overlay origin is shifted by `B * s` so overlay coordinates are trim-relative.

Zoom steps (L5970): `Z = [.5, .75, 1, 1.25, 1.5, 2, 3, 4]`; `+` = next larger, `−` = next smaller, the percentage button = 1 (fit). Buttons disable at ≤ .5 and ≥ 4. Step-4 page view uses the same `ui.zoom` through CSS (`--z`, L2389).

### 6.2 Selection

- Target = `e.target.closest('[data-el]')` — i.e. the browser's own SVG hit test, which follows paint order (`L.z`). Elements with transparent areas carry an invisible full-box rect so the whole frame is clickable.
- `data-el="bg"` (paper rect / Pozadí layers) → selects `bg`; no frame is drawn for it (`c.L.e.bg` does not exist).
- Pointer down inside the canvas but not on an element, or on the stage outside the canvas (not on a button) → deselect.
- Layer row click (L5927): toggles (`sel === k ? null : k`), clears `part`; selecting `cal` sets `calOpen = true`.
- Esc (L6208): part → whole kalendárium → nothing.
- Frame: 8 handles `nw n ne e se s sw w`; with a part selected the frame is dashed/dim, has **no handles**, and the tag reads `Kalendárium › <part>`.
- Part highlight: one `.cal-pbox` per SVG node with that `data-cp`, from `getBoundingClientRect` (+3 px / +2 px padding).

### 6.3 Move / resize

- Drag starts after `Math.hypot(dx·s, dy·s) ≥ 3` screen px. First movement: `calSnapshot(c)` (once), `ui.part = null`, `body.cal-drag`.
- Positions are always computed from `start = { ...b }` (the box at pointer down) and `base` (deep copy of all boxes at pointer down).
- Resize maths: `e`: `w = start.w + dx`; `s`: `h = start.h + dy`; `w`: `w = start.w − dx, x = start.x + dx`; `n`: `h = start.h − dy, y = start.y + dy`. Minimum before snapping: `if (r.w < 20) { if (mode has 'w') r.x −= 20 − r.w; r.w = 20 }`, same for `h < 12` with `'n'`.
- Then snap (unless Alt), then clamp, then **round x, y, w, h to 0.5 unit**, then link, then re-render the SVG + overlay live.
- Clamp for move (`calClampBox`, L5849): `w ≤ CW + 2B`, `h ≤ CH + 2B`, min 20 × 12, `x ∈ [−B, CW + B − w]`, `y ∈ [−B, CH + B − h]`.
- Clamp for resize (`calClampEdges`, L5851): each edge individually to `[−B, CW + B]` / `[−B, CH + B]`, then min 20 × 12.
- Minimum size: **20 × 12 units** (= 2 % of the page width × 2.56 % of the height; 6.2 × 3.7 mm at 310 × 145).
- Arrow keys (L6209–L6210): `±1` unit, Shift `±10` units (0.1 % / 1 % of the width; 0.31 / 3.1 mm at 310 mm), `calSnapshot` per key press, `calClampBox`. Ignored when a part is selected, when focus is in `input, select, textarea`, or when a `<dialog open>` exists.
- Typed X / Y / Š / V (`calNumSet`, L6043): `b[g] = v / CAL_MM; calClampBox(b, B)`; for `w`/`h` with linking on → `calLink(c, sel, from, b, base)`. Field step 0.5 mm; shown with one decimal and a decimal comma; Enter blurs (L6120). Note `calClampBox` (the *move* clamp) is used, so an over-wide value shifts `x` instead of stopping the edge.

### 6.4 Snapping (`calSnap`, L5822–L5837)

```js
th = 6 / (c.ui.s || 1)                                   // 6 screen px
xs = [−B, 0, CW / 2, CW, CW + B]
ys = [−B, 0, CTOP, (CTOP + CH) / 2, CH, CH + B]          // 40 = lower edge of the band, 254 = centre of the area below it
+ for every other element that is not `hide`: x, x + w → xs; y, y + h → ys   (positions from `base`, i.e. at drag start)
best(vals, cands) = the candidate with the smallest |target − value| ≤ th over all value × target pairs
move:   x-candidates [x, x + w/2, x + w], y-candidates [y, y + h/2, y + h]; one winner per axis; shift the box
resize: only the dragged edge(s): 'w' → x, 'e' → x + w, 'n' → y, 's' → y + h; the edge moves, the opposite edge stays
```

Guides: `{ v: x }` / `{ h: y }` per snapped axis, drawn full trim height / width, cleared on pointer up. Alt → no snapping, no guides. There is no horizontal centre line of the whole page and no element-centre targets.

### 6.5 Propojit prvky (`calLink`, L5841–L5848)

```js
function calLink(c, k, from, to, base) {
  const E = c.L.e, pageX = (v) => v < .6 || v > CW - .6, pageY = (v) => v < .6 || v > CH - .6;
  const ed = [['l', from.x, to.x, 'x'], ['r', from.x + from.w, to.x + to.w, 'x'], ['t', from.y, to.y, 'y'], ['b', from.y + from.h, to.y + to.h, 'y']];
  Object.entries(E).forEach(([n, o]) => { if (n === k || o.hide) return; const b0 = base[n]; Object.assign(o, b0);
    ed.forEach(([, a, z, ax]) => { if (Math.abs(a - z) < .01 || (ax === 'x' ? pageX(a) : pageY(a))) return;
      if (ax === 'x') { if (Math.abs(b0.x - a) < .6) { const r = o.x + o.w; o.x = Math.min(z, r - 20); o.w = r - o.x; } else if (Math.abs(b0.x + b0.w - a) < .6) o.w = Math.max(20, z - o.x); }
      else { if (Math.abs(b0.y - a) < .6) { const r = o.y + o.h; o.y = Math.min(z, r - 12); o.h = r - o.y; } else if (Math.abs(b0.y + b0.h - a) < .6) o.h = Math.max(12, z - o.y); } }); });
}
```

- Called on every pointer move of a **resize** (`mode !== 'move'`) when `calLinked(c)`, with `from = start`, `to` = the already snapped / clamped / rounded box, `base` = all boxes at drag start; and from typed Š / V.
- Every follower is first reset to its `base` box, so nothing accumulates.
- An edge of A participates when it actually moved (`|a − z| ≥ .01`) and did **not start on or beyond the trim edge** (`v < .6 || v > CW − .6`, resp. `CH`).
- A follower's left edge is tested first, then (else) its right edge — one edge per axis per A-edge. Tolerance `.6` unit (0.19 mm at 310 mm).
- Follower minimum 20 × 12; the far edge stays.
- Followers are not snapped, not clamped to the bleed and not rounded themselves (they land on A's rounded edge).
- Toggle: `ui.link = !calLinked(c)` + toast (L5924). Default on because `ui.link` is undefined.

### 6.6 Kalendárium parts

- Pointer down on a kalendárium node (L6178–L6200): if `cal` was **not** selected → select the whole block (and a drag moves it). If it was selected and the pointer goes up **without movement** on a node with `data-cp` → `ui.part = that part`. If it moves → the whole block moves and `ui.part = null`.
- Part offset drag (L6181–L6186): only when the pointer goes down on a node of the **already selected** part. `nx = round((o0.x + dx) * 2) / 2`, same for y; without Alt `|nx| < .75 → 0`, `|ny| < .75 → 0`; zero offset deletes `st.off[part]`. Snapshot on first movement (3 px threshold).
- Reset: `data-cloffrst` deletes `st.off[ui.part]` (L6031).
- **Event box handles** (`data-clevb`, L6155–L6162): start box from `getBBox()` of the first `[data-evbox]` and the first `[data-day]`; `e`: `w = max(20, w0 + dx)`; `w`: `w = max(20, w0 − dx), x = x0 + w0 − w`; `s`: `h = max(4, h0 + dy)`; `n`: `h = max(4, h0 − dy), y = y0 + h0 − h`; stored rounded to .5 in `st.ev.box`. Moving the box as a whole = the ordinary part-offset drag of `ev` (`st.off.ev`). Reset (`data-clevbr`, L6030): delete `st.ev.box` and `st.off.ev`.
- **Icon cell handles** (`data-clicw`, L6163–L6167): `C.icCell = max(6, round((W0 ± dx) / n * 2) / 2)`, `W0` = current grid width in units, `n` = number of columns (`data-icgrid`: 4, 2, or the slot count in row mode).
- **Holiday wrap handles** (`data-clhw`, L6168–L6172): `St.hol.ww = max(20, round(w0 ± dx))`, `w0 = St.hol.ww || current group width`.
- Each handle drag: snapshot on first movement, live re-render, full re-render on release.

### 6.7 Layers

- Rows = `L.z` (QR row only when `gen.qr.on`), plus the fixed **Pozadí** row. Drag & drop (L6125–L6132): drop above/below the target row by the pointer's position relative to the row's vertical middle; `calSnapshot`; `z` rebuilt.

### 6.8 Undo / redo

`calSnapshot` (L5854): `c.hist.push(JSON.stringify(c.L)); if (c.hist.length > 60) c.hist.shift(); c.fut = [];`. `calUndo` (L6047–L6050): move the current `L` to the other stack, restore, clear the selection if the selected element is now hidden. Not while dragging, at most 3 passes. Never shrinks. It runs against the **sample page only**, mutates the layout without an undo snapshot and without marking it as a user change.

## 10. Behaviour the handoff does not mention, or where prototype and handoff differ

Data and defaults

1. **Demo content is seeded into every calendar**: ten events (`CAL_EVD`), five clubs, four waste kinds with rules and place names (`Rudoltice 102`, …), the extra name `Vasil` on 2 January. Handoff check G9 relies on *Karina / Vasil* only "with the extra name Vasil on that date", so start empty unless told otherwise.
2. **Special pages**: switching the feature on turns **Důležité kontakty and Roční kalendárium on immediately** (`calSpList`, L4926), which also flips the back page to "Kontakty klienta". Handoff lists special pages as off until chosen.
3. Step 1 is a plain checklist; week-number form lives in the Číslo týdne panel (**Tvar**), which writes to `gen.wk.fmt` (content, not style → not undoable, not part of a loaded layout).
4. `Označit vše` does not update `e.cap.hide` (only the single `cap.on` checkbox does, L6109). The eye button of Popisek fotografie toggles only `e.cap.hide`, never `gen.cap.on`. So the "same switch seen from two places" of the handoff is one-directional in the prototype; the caption is drawn only when **both** allow it.
5. The caption placeholder `Popisek fotografie, autor` is printed on every page without a caption, including the print preview and the client view.

Editor

6. The red dashed **event box** and the violet **icon cells** are drawn in every row whenever the editor page is shown — not only while Akce / Ikony is selected, and the event box even when events are off (L5233, L5260). The handoff describes them as appearing on selection.
7. **Undo covers `c.L` only.** Several editor actions take a snapshot but change `c.gen`, so undo does not revert them: add/remove an icon category (L5942–L5943), reorder icon categories (L6140), waste colours (`g:` colour keys), custom waste/event icons (L6066–L6067), event icon name. The handoff requires every layout or style change in the editor to be undoable — these settings should live with the style.
8. **Sliders are not undoable**: the `input` handler applies the value live (L6116, L6117, L6119) and the `change` handler takes the snapshot *afterwards* (L6060, L6086, L6071 → `calNumSet`), so the snapshot already contains the new value. Affects all **Velikosti** sliders, opacity sliders, gradient angle, moon size slider. Handoff: "Sliders … count as one undo step".
9. **Icon order is unstable.** `calGen` (L4957) rewrites `gen.iconOrder` on every call against the key set *waste kind keys + `moon` + `ev`*, dropping the category keys `waste`, `time`, `season`; `calIconOrder` (L4964–L4965) then maps kind keys back to `waste` and appends the missing categories. Net effect (confirmed by replaying the two transcribed functions in isolation): a new calendar starts as `waste, moon, ev, time, season`, the second render makes it `moon, ev, waste, time, season`, and after any user reorder only the relative order of `moon` and `ev` survives — `waste` always lands after them and `time`/`season` last. Port the intent (an ordered list of the five categories, position 1 nearest the outer edge), not this code.
10. Elements whose **feature** is off are still snap targets and link followers: `wk` when "Zobrazení týdnů" is off and `qr` when QR is off are not drawn but have no `hide` flag (L5825, L5844). Handoff: hidden/absent elements must be ignored.
11. Mirroring does not flip `cap.align`, `num.align`, `ev.align`, `time.align`, `cal.dayAl`, part offsets, the event box x, or icon cell alignment (§3.2). Handoff: "text alignment and the day-number side flip too".
12. Text auto-grow (§6.9) checks only the sample week, is not an undo step, and happens on mere display. Other weeks with a longer month text can still overflow.
13. Typed Š/V use the move clamp (`calClampBox`), so a value larger than the available space shifts the element instead of stopping the edge; typed values are not rounded to the 0.5 grid.
14. Layout file: accepts `{ L: { e, st } }` or `{ e, st }` and validates only the presence of `e` and `st` (L6093); there is no way to save one (handoff Q5). Loading a layout from another calendar offers every calendar with a layout, regardless of type.
15. The undo/redo **buttons** exist only in step 3; in step 4 "Styl stránek" only the keyboard shortcuts work.
16. Number styles have **separate** part offsets (`num`, `numSat`, `numSun`, `numHol`), while horizontal alignment is shared (`num.align`).
17. Kalendárium details not in the handoff: rows use `b.h − 6` (a 6-unit slack at the bottom); a line is drawn under the last row too; the text block is vertically centred on weekday + name only; holiday names wrap by an estimated character count; in compact mode a holiday name is truncated to 28 characters + `…`, only one of holiday / events / time text is printed, there is no event box and shift columns collapse to one text line; photo corner radius does not clip an uploaded photo.
18. Zoom "fit" is capped at 1.6× and floored at 0.3× of unit scale (L5808); `ui.zoom`, like the rest of `ui`, is persisted with the calendar (not in the layout).

Generation and content

19. **Year change** (L5915) rewrites only the year prefix of `ev.list[].date`, `names[].date`, `waste.types[].dates` and reseeds `moonList`. It does **not** touch `fromD`/`toD` (a waste range with exact dates stays in the old year and then matches nothing), `extra` collections, `comments[].iso`, or `c.pages` keys (which embed week number + date range, so all per-page photos/captions are silently orphaned). 29 February is shifted textually to a non-existent date.
20. **Type change** (L5914) changes nothing but `c.type`: no confirmation, no layout reset; page keys change (the range differs), so overrides are orphaned.
21. 14-day week texts in forms `b`/`c` are `Týdny 53–1` / `T53–1` (§5.2).
22. Month text across two months of the same year prints the year once: `LEDEN / ÚNOR 2027`.
23. Waste even/odd/4-week rhythms follow ISO week numbers and break at a 53-week year boundary; "První v měsíci" = day-of-month ≤ 7; `extra` dates ignore the range. Season starts are fixed dates. Moon phases are a mean-cycle approximation.
24. Bulk photo upload (L6096–L6097): images only, sorted with `localeCompare(…, 'cs', { numeric: true })`, first `weeks.length` files, EXIF/XMP caption overwrites the caption only when present; it does not reset crop/zoom and does not record pixel size (handoff §8 requires both on every upload path).
25. Event text is limited to 4 events per day (`slice(0, 4)`); a 5th is silently dropped without a warning.
26. Renaming a club's code propagates to its events (L6057); a new club gets the code `S<n>`.
27. Waste date picker navigates December of the previous year … January of the next (`ui.wm` −1…12) but the month strip shows only the 12 months of the calendar year.

Preview, roles, saving

28. Crop marks are **6 mm** long starting 2 mm outside the bleed (§4.6); the code comment says 5 mm.
29. Client view is a UI switch only (`viewAs() === 'user'`, L5330): step forced to 5, tools limited to photo / waste / events / names, trimmed page. Still available to the client in the prototype: the calendar name field, **Uložit**, **Historie**, the warnings chip, and — inside the content dialogs — the `Zapnout` button that switches a step-1 feature on (L5649, L5976). The client link is a fabricated URL `https://app.wboost.cz/k/${c.id}`.
30. Designer's step-5 toolbar shows all seven tools (disabled ones dimmed); warnings and plus buttons are positioned from `getBoundingClientRect` of the rendered SVG; the plus buttons sit outside the kalendárium on its outer side (`right = cal centre > CW / 2`).
31. Saving: only **Uložit**, Ctrl+S and Dokončit write to storage. A newly created calendar that was never saved disappears on reload, and **deleting a calendar is not persisted** until some later save (L5888 has no `calSave`). The name field does not set the unsaved flag.
32. Opening an unfinished calendar returns to `c.step` only if that step was saved; the stored `ui` also restores the selection and open dialogs.
33. History: capped at 200 entries; several step-5 changes are not logged (§8.13).
34. Step-5 popovers: Enter confirms only from `<input>` (not from the comment textarea); Esc closes without saving; an empty event name or comment refocuses the field (L6002–L6003).
35. The whole workspace is re-rendered from strings on every change, with scroll positions and focus restored by hand (`calRe`). Treat this as an implementation shortcut, not behaviour to keep.
