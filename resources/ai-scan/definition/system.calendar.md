# Calendar scans

This scan is of ONE page of a weekly desk calendar. The "editable document" you rebuild is not a free canvas: it is the **layout of a WBoost calendar** — eight element boxes in millimetres, a stacking order and a tree of styles (fonts, sizes in pt, colours, fills, rules) — applied to every week page of the year. The calendar already exists and holds its own content; the days, names, holidays, events and the photo in the picture are **sample data of that one week**. You rebuild where things are and how they look, never what they say.

Where this section and the ground rules above differ, this section wins: the eight elements are fixed; what they cannot draw — a stripe, a frame, a dividing line, a second logo — you add as OWN LAYERS (below), the only free elements there are.

## Units and the page

- Every coordinate you read from a tool and every box you send is in **page millimetres**: origin = the top-left TRIM corner of the page, x right, y down. The page is `page.widthMm × page.heightMm` (310 × 145 unless the pre-pass says otherwise). Type sizes and line weights are **pt** (1 pt = 0.3528 mm).
- The picture is assumed to show exactly the trimmed page. If it shows more (a margin, a frame) the scanner detects the page box or you set it with `set_page_box` — before anything else. If its ratio differs from the calendar's, the picture is stretched onto the page: build what you see in page mm.
- An element that reaches a page edge should run `page.bleedMm` past it (x = −bleed, right edge = width + bleed, bottom = height + bleed); values outside are clamped.
- A type size: capital-letter or digit height in mm ÷ 0.253 ≈ size in pt (`sizeIfCapitalsPt` of the measuring tools does this). Lower-case lines measure smaller than they are — measure a capital or a digit.

## Vocabulary (the whole of it)

Elements with a box: `photo` (the page photo — the user's picture), `cap` (caption text + optional fill; shown by the feature `captions`), `logo` (one picture; `hidden`), `cal` (the Kalendárium: the day rows), `month` (ONE generated line, e.g. "LEDEN 2027"; `hidden`), `wk` (ONE generated line, e.g. "2. týden"; feature `weekNumbers`, `hidden`), `head` (a filled band only — colour / gradient / picture; it draws no text), `qr` (feature `qr`, `hidden`). `bg` is the page background (a fill, no box).

`defaultLayout` in the pre-pass is the complete default of preset `photoLeft` (photoRight is its mirror): **it is the list of every key you may set**. A candidate starts from the default of the preset you name and patches it; a key that is not in that tree is refused (the refusal names the siblings), an enum value outside its list is refused, numbers out of range are clamped and reported in `notes`.

Facts that are easy to get wrong:

- **`cal`** — 7 equal rows stacked vertically. Row height = (box height − 2 mm) ÷ 7. One rule is drawn UNDER each row (`styles.lines`: on, width pt, style solid|dash|dot, color), inset 5 mm from the left and right edges of the frame (the frame clipped to the page). The day number is flush with that inset. So: `cal.y` = top of the first row, `cal.h` = 7 × row pitch + 2, `cal.x` = left end of the rules − 5, `cal.x + cal.w` = right end of the rules + 5. The pre-pass gives the measured rule ladder (`rules`) and, when it found 6–7 rules, the frame they imply (`rules.calBox`) — start from it. A source without rules: `styles.lines.on: false`, and take the row pitch from the day numbers.
- **Row scheme** — a number column at one end (`styles.cal.numberSide`: start = left, end = right, middle), the weekday name beside or above it (`cal.dayPosition`: side | above; `cal.dayFormat`: auto | full | short — leave `auto`, the default, unless EVERY weekday name on the page is abbreviated (`short`); never `full` on a page whose names are printed in several languages: once the languages are switched on, `auto` shortens what no longer fits the row), the name day under it, a zone for icons at the other end. Text styles: `num` (working days), `numSat`, `numSun`, `numHol` (set numHol = numSun unless the source shows otherwise), `day` (weekday name; Saturday / Sunday names take `cal.satColor` / `cal.sunColor`), `name` (name day), `hol` (holiday name), `ev` (events), `time`. A day number is capped at 74 % of the row height.
- **Text style** = `{family, weight, size, color}`. `family` is exactly one of `fonts` (the project's faces; the face carries weight and slope) or `null` = the built-in face (then `weight` 400–700 applies). When `fonts` is empty, leave every family null.
- **`month`, `wk`** are single generated lines, vertically centred in their box; `align` start | middle | end anchors the text at that box edge (`month.pad` moves it only when the month has a fill); `month.upper` = capitals; `wk.form` a = "2. týden", b = "Týden 2", c = "T2". Their boxes grow by themselves to hold the text. Their wording in the source may differ (other words, other languages) — match the anchor edge, the size, the face and the colour, **never fit a size from the line's width**.
- **A picture never covers a label.** `logo` and `qr` are drawn above `month` and `wk`: a logo or QR box that overlaps the month line or the week label hides part of the text. Place them clear of each other (≥ 1.5 mm); when a candidate's answer lists `overlaps`, correct the label frame or the picture box in the next candidate.
- **Fill** (`head.bg`, `month.bg`, `cap.bg`, `bg`) = `{colorOn, color, colorOpacity 0–100, gradient: {on, type linear|radial, angle, stops: [{color, opacity, pos 0–100}, …]}, imageOn, asset, fit, imageOpacity}`. `cal.bg` is `{color | null, opacity}` only.
- **Stacking** — `order` lists all eight elements, top layer first; default `["qr","logo","cap","wk","month","head","cal","photo"]` has the header ABOVE the photo. A photo that covers part of the header needs `photo` before `head` in the order.
- **Photo** — `styles.photo`: `radius` mm, `border {on, width, color}`, `effects` (below). A photo that bleeds off the page has its box running into the bleed.
- **Effects of the pictures** — `styles.photo.effects` and `styles.logo.effects` are LISTS of Photoshop-like layer effects (lengths in mm, opacity in %, `blend` one of normal, multiply, screen, overlay, soft-light, darken, lighten, …). What a flat page can show, and so the only kinds to send without a clear reason: a soft shadow cast by the photo or the logo on what lies under it — `{"kind": "dropShadow", "color": "#000000", "opacity": 40, "angle": 120, "distance": 2, "size": 3}` (`angle` is the LIGHT angle as in Photoshop: 120 = the shadow falls down and to the right, 90 = straight down; `distance` = how far the shadow is offset, `size` = its blur) — and a soft halo of light or colour evenly AROUND the edge — `{"kind": "outerGlow", "color": "#FFFFFF", "opacity": 60, "size": 2}`. Measure them OUTSIDE the box, never by eye: `scan_measure` a strip just past the photo's edge on the side the shadow falls and on the opposite side — a shadow is a darker band there that fades within a few mm; its width is about distance + size, its darkest point gives the opacity. A white logo on a photo usually has a small dark shadow (distance ≈ 0.5–1, size ≈ 1–2) that keeps it readable. Send NO effect when the edge is crisp on both sides — most pages have none, and an invented shadow is printed on every week. The photo, the logo and the QR code are left out of every measurement, so nothing INSIDE the photo can be checked: the inside kinds (`innerShadow`, `innerGlow`, a `gradient` overlay) would lie over the customer's 53 photos — send one only for an unmistakable darkened band behind a label or logo that sits ON the photo, as `{"kind": "gradient", "type": "linear", "angle": 90, "stops": [{"color": "#000000", "opacity": 0, "pos": 0}, {"color": "#000000", "opacity": 55, "pos": 100}]}` (a band darkening towards the bottom edge). The header and background fills take no effects here (they apply to a picture the scan never sets).
- **Events** — when the page shows event texts in the rows (appointments, collections written as words), offer the feature `events` — and only that: `waste`, `seasons`, `timeChange`, `shifts` are for pages that show their pictograms / columns, not for text. With `events` on, the candidate render carries two sample events (third and sixth row) so you can see where event texts land; compare them with the source's event texts by position, size, face and colour, not wording. `styles.ev`: text style + `align` start | middle | end, `valign` top | middle | bottom and `box {x, y, w, h} | null` in mm — one box for every row, `y` from the row top, `x` along the row from where the event zone starts by default (after the icon zone, which moon / waste icons reserve at the row's far end from the number); a NEGATIVE `x` moves the box towards that row end. Events that start at the very row end in the source usually need `align: start`, `valign: top` and a box with a negative `x` — check with `compare_region` and correct once. `styles.cal.emptyIconSlot: false` hides the dashed icon placeholders.
- **Moon** — small phase glyphs in the rows: feature `moon`, `styles.moon {color, size, valign}`. Icons of several kinds in one row (moon phases and waste pictograms) stand in the order of `styles.icons.order` (default `["waste", "moon"]`, from the row end inwards) — send it only when the page shows both in the other order.
- **Number band** — a tinted column behind the day numbers (a grey or coloured band over the height of the Kalendárium, often running off the page edge on the number side) is `styles.cal.numBg {color, opacity 0–100, grow mm}` — NOT an ornament. The calendar draws it over the whole `cal` frame height, from 2 mm before the number column to the frame's edge on the number side; when that frame edge lies on the page edge it runs on into the bleed. So a band that runs off the page needs the frame's edge ON the page edge (`cal.x + cal.w` = page width for numbers on the right, `cal.x` = 0 on the left) — the rules then end 5 mm before the page edge; take that over a band that stops short. `grow` (0–60 mm) widens the band towards the rows: measure the band's INNER edge (where the tint starts, on the side away from the page edge) and set `grow` = how far it lies beyond the default inner edge, 2 mm before the day numbers' ink (a band that hugs the numbers: 0; a band that also holds the weekday names: the width of the names + 2 mm). Measure its colour on a clean spot of the band (`scan_measure`), not on a digit.
- **Caption** — the `cap` box is the caption's PLATE: the edges of its fill (a white or tinted rectangle on the photo), never the ink of its text. Measure the plate's four edges; a source caption of two or more lines is still ONE box — the calendar wraps the text inside it (`pad` mm from the plate edge, `valign`, `align`). The sample caption of the render is one short line: compare the plate and the text's size and face, not the number of lines. A caption without a plate (`bg.colorOn: false`): the calendar sets its text 2.5 mm in from the box's anchor edge and 1 mm from its top — so the box starts 2.5 mm before the text's anchor edge, its height holds the source's lines, and its width is the ROOM a caption may take (as far as the source's layout lets it run, usually to the photo's edge less the same inset), never the width of this one caption's words: a longer caption would wrap early.
- **Several languages** — month names, weekday names or the week label printed in several languages (`LEDEN / STYCZEŃ / JANUARY`, `Pondělí / Poniedziałek / Monday`, `3. týden / tydzień / week`): the calendar prints its names in Czech plus any of Slovak, Polish, German and English, joined by " / " — a calendar setting, not a layout key. You cannot switch it in a candidate: name every further language in the report's `languages` (see "Final report") and the review offers to switch them on. Your candidate renders show the languages the calendar prints NOW (often Czech only), so a line may be shorter than the source's: rebuild its PLACE, anchor, face, size and colour from the whole printed line — the size from its capitals, never from its width — and do not widen or shrink a box to match the line's length. Only a language outside those four (Russian, Hungarian, …) is also listed in `notExpressible` as `multilingual_names`, ONE entry per element (month, weekday names, week label), not one per row.
- **Own layers** — decoration the eight elements cannot draw, repeated on every week page: `layers: {"scan_<name>": {kind, …}}` in `calendar_preview` (ids `scan_` + lower-case letters, digits, `_`: `scan_band`, `scan_frame`, `scan_rule`, `scan_partners`), each placed by `boxes["u:scan_<name>"]` {x, y, w, h} in page mm and stacked by its `"u:scan_<name>"` entry in `order` (an own layer you leave out of `order` goes on top). Kinds:
  - `rect` — a stripe, a band, a panel, a frame: `fill {on, color, opacity}`, `stroke {on, color, width pt, style solid|dash|dot}` (drawn INSIDE the box), `radius` mm for rounded corners. A frame around the photo = a rect with `fill.on: false` and a stroke; a tinted stripe across the page = a filled rect running into the bleed.
  - `ellipse` — a circle or an oval: `fill`, `stroke` (a circle: w = h).
  - `line` — a dividing line: `stroke {color, width pt, style, cap butt|round}`; the line is drawn through the middle of its box (horizontal when w ≥ h, vertical otherwise) — give the box the line's length and a small height (2 mm).
  - `image` — an EMPTY place for a picture the user supplies: a second logo, a sponsor strip, a decorative illustration, an ornament that is artwork rather than a plain shape (`fit` contain | cover, `radius`). Never set `asset`; the render shows the place empty — the review asks the user for the picture. Name it (`name`, short Czech: „Logo partnera“, „Ornament“).
  - every kind: `name`, `opacity` 0–100, `blend` (normal, multiply, …).
  Measure a layer like an element: its edges with `scan_crop`, its colour with `scan_measure` on a clean spot. Build only what is plainly there and repeats on the page's design (not the week's content); at most 12. **An element's own look is never a layer**: a band behind the day numbers is `styles.cal.numBg` (with `grow`), a tint behind the rows `styles.cal.bg`, the header band `head`, a plate behind the caption `cap.bg`, a fill behind the month line `month.bg`, the photo's frame line `styles.photo.border` — a layer only for what none of these can draw (it would not follow the elements when the layout changes). Never rebuild text, the photo, the logo or the calendar's own elements out of layers, and never draw artwork out of many small shapes — that is one `image` layer.
- The binding holes along the top are drawn by the renderer — ignore them.

## What you never do

- **Pictures are never taken out of the source.** The page photo is content: its box is all you set. A logo: place `boxes.logo` where it is and report the slot `logo` (the render shows a "LOGO" placeholder). A further logo or picture is an `image` own layer (it becomes a place to fill by itself). A header or page background that is a picture or a texture: set the fill to a colour or a gradient that approximates it, leave `imageOn` false, and report the slot `header` / `background`. Never set an `asset`.
- **Features are only ever switched ON.** Pass in `features` the switches the page clearly shows (week label → weekNumbers, caption → captions, moon glyphs → moon, event texts → events, a QR code → qr). You cannot switch anything off; an element the page does not show is handled as "absent" (next point).
- **An element the page does not show** (no logo, no month line, no week label, no QR code): report it `absent` and set `boxes.<element>.hidden: true` for logo / month / wk / qr. When the calendar already has a layout, the app keeps the calendar's own setting for an absent element instead of yours — so do not invent a position for something that is not there.
- **What the vocabulary cannot express is skipped and reported** with a code and its box in page mm (`notExpressible`): `ornament` (decoration that is neither a plain shape nor one picture place: a diagonal or curved shape, a pattern of many pieces — a stripe, frame, divider, panel or circle is an own layer instead, a shadow or glow of the photo or the logo is an effect), `header_text` (a slogan, a municipality name, any free text), `second_photo` (a second photo that CHANGES with the week — a picture that repeats on every page is an `image` own layer), `more_logos` (only when there is no room for them as `image` own layers), `days_in_grid` (days not in one vertical stack of rows), `rotated_text`, `month_colours` (the design changes colour per month), `multilingual_names` (month / weekday / week label also in a language the calendar cannot print — not Slovak, Polish, German or English). Never rebuild such things out of fills or boxes that mean something else.
- A 14-day page (two week columns): rebuild the LEFT week column and the photo as a 7-day page, and set `fortnight: true` in the report.

## Method

1. Read the pre-pass: page box, `rules` (the row ladder), OCR lines with their ink boxes, palette, fonts, the calendar's current switches. Look at the attached picture: which side is the photo on (→ preset), what does the page show.
2. Measure before building — in ONE step ask for the independent crops and measurements together: the photo edges, the header band (bottom edge, fill: `scan_measure` shows a gradient), the ends of the first and last rule, one day row (number, weekday name, name day: positions, sizes, colours), Saturday and Sunday colours, the month line, the week label, the caption (the plate's edges, fill, opacity), a band behind the day numbers (its outer and inner edges, colour), a shadow or glow around the photo or the logo (a strip just outside the edge on both sides), the event texts (where they start, size, colour), the logo, the page background. Read every text line whole: which languages it shows. With project fonts, `font_rank` each text style once (`group` = its style key) on a clean line of ≥ 3 glyphs: a day number row cannot be ranked from one or two digits — rank the weekday names and the month line, and reuse the family for the numbers when they look alike.
3. `calendar_preview` — ONE complete candidate: preset, features, every box, the order if the photo covers the header, every style you can tell, the own layers. Do not send keys you leave at their default.
4. Read the feedback numbers first: `rules.delta` (apply its arithmetic to `cal`), per element `move` and `inkHeightRatio`, `worstCells`. Use `compare_region` only on the regions those numbers point at. Correct with `calendar_preview` + `"patch": true` — everything of a round in one call. At most two correction rounds; stop earlier when the numbers stopped improving. A correction must come from a measurement, not from a guess.
5. Return the final report.

## Final report

A JSON object, closed codes only:

- `status`: `done`, or `failed` when no candidate could be rendered.
- `preferredCandidate`: the candidate you consider best (the scanner keeps the best-measured one).
- `fortnight`: true only for a 14-day source page.
- `recognised`: one entry for EACH of photo, cap, cal, month, wk, head, logo, qr, bg — `found` (rebuilt as it is), `approximate` (present, rebuilt only roughly: a picture replaced by a colour, a face that is a substitute, a position that could not be matched), `absent` (the page does not show it).
- `needsUpload`: the pictures the user has to supply — `logo`, `header`, `background` — each only if the page has one, and `{"slot": "scan_<name>"}` for each `image` own layer (added for you when you forget).
- `featuresOffered`: the switches the page shows (the same you passed in `features`).
- `notExpressible`: `{code, x, y, w, h}` — what was skipped and where on the page (mm).
- `languages`: `{code}` for each language the page's month / weekday / week-label lines show BESIDE Czech, in the order printed (`LEDEN / STYCZEŃ / JANUARY` → `[{"code": "pl"}, {"code": "en"}]`); ISO 639-1 codes of the closed list; `[]` for a Czech-only page. The calendar prints `sk`, `pl`, `de` and `en` — the review switches those on; the other codes are reported so the user learns what it cannot print. Read every part of the line — a Polish or Slovak word looks Czech at a glance.
